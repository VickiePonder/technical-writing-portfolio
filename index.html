Featured case study · 2026

From a weekly reporting bottleneck to a standardized PMO workflow.

The challenge was bigger than reporting: project updates were collected through repeated follow-ups, manually transferred from Jira into spreadsheets, and emailed to the CIO once a week. The redesigned operating model standardized intake, approvals, project setup, documentation, and executive visibility.

Before · manual process

35 hours of follow-up and consolidation each week

Approximately 40 PMs were contacted for status updates. A portfolio manager chased responses, copied Jira data into a spreadsheet, and emailed a static report to the CIO by Friday. The next consolidated view waited another week.

After · implemented approach

Standardized intake and refreshed dashboards

Forms and Power Automate route approvals and initiate templated project setup. PMs maintain status in Jira; Power BI dashboards embedded in SharePoint refresh multiple times daily, giving leaders a current view without depending on a weekly email cycle.

flowchart TD

02 / After: standardized operating model

flowchart TD
A["Project request via Microsoft Forms"] --> B["Power Automate approval routing"]
B --> C{"Two-director approval"}
C -->|Approved| D["Create project record and templated SharePoint site"]
C -->|Not approved| X["Return / close request"]
D --> E["Set up Teams, Jira structures and documentation"]
E --> F["PMs maintain standardized project updates in Jira"]
F --> G["Power BI dataset: scheduled refreshes multiple times daily"]
G --> H["Power BI dashboards embedded in SharePoint"]
H --> I["Leadership reviews portfolio health, milestones and risks"]

Documentation deliverables: Workflow architecture, approval logic, SharePoint templates, Jira conventions, implementation runbooks, validation checklists, and rollout guidance. The previous 35-hour weekly workload is a baseline; realized savings have not been independently measured here. Dashboard data freshness depends on scheduled refresh and source updates.
